## 0. 本周主线（先建立全局认知）

本周核心是**面向对象三大支柱**与**类之间的关系**：

- **封装 / 信息隐藏（encapsulation / information hiding）**：`private` 实例变量 + `public` 的 getter/setter。〔12 p8-10〕〔09 p5〕
- **继承（inheritance, is-a）**：`extends`，子类复用并特化父类。〔11 p6-7〕
- **多态（polymorphism）**：用父类型引用指向子类对象，统一处理。〔11 p29-30〕
- **抽象（abstraction）**：抽象类（abstract class）与接口（interface）定义"必须有什么行为"，不给（或少给）实现。〔11 p32-36〕〔13 p8〕

两种类间关系（务必区分）：
- **聚合 has-a（aggregation）**：对象作为另一个类的实例变量。如 Kitchen has-a Refrigerator。〔11 p4, p20〕
- **继承 is-a（inheritance）**：如 Triangle is-a Shape。〔11 p21〕

## 1. 编写一个 OO 类的标准 7 步（核心方法论）

> 出处：09 银行账户示例〔09 p1-13〕；10 课件复述同样 7 步〔10 p9〕。

开发一个 Java 类的标准流程〔10 p9〕：

1. 决定类要做什么（what the class is supposed to do）
2. 列出实例变量与方法（list instance variables & methods）
3. 为方法写 **prep code**（伪代码 pseudocode）
4. 为方法写 **测试代码**（test code）
5. 实现类（implement）
6. 测试方法（test）
7. 调试并重新实现（debug & re-implement）

### 1.1 UML → Java 代码的映射〔09 p3〕

| UML | Java |
|-----|------|
| 属性 attribute（account number / name / balance） | 实例变量 instance variable（`int accNo` / `String accName` / `double balance`） |
| 操作 operation（deposit / withdraw） | 方法 method（`deposit(double amount)` / `withdraw(double amount)`） |

> 记忆点：**实例变量定义对象的状态（state/attributes），方法定义对象的行为（behaviour）**。〔09 p3〕

### 1.2 一个 Java 类的通用模板〔09 p4〕

```java
class ClassName {
    // instance variables  实例变量
    // constructors        构造器
    // accessors (getters)  访问器
    // mutators (setters)   修改器
    // service methods      服务方法
}
```

- **Step 1 实例变量**：默认全部用 `private`（信息隐藏）。〔09 p5〕
- **Step 2 构造器 constructor**：与类同名、无返回类型；用 `this.x = x` 区分参数与字段。〔09 p6〕
- **Step 3/4 getter/setter**：仅在允许外部读/改时提供。如银行账号不可被 set；balance 不能直接 set，只能经 `deposit()/withdraw()` 改。〔09 p7〕
- **Step 5 服务方法 service method**：操作并改变对象状态，如 deposit/withdraw。〔09 p8〕
- **Step 6 `toString()`**：见 1.3。
- **Step 7 测试类 test class**：写 `main()` 实例化对象并验证。〔09 p13〕

### 1.3 `toString()` 方法（高频考点）〔09 p9-11〕

- 直接 `System.out.println(myAccount)` 会输出 `BankAccount@119c082`（类名@散列码），因为编译器不知道如何表示该对象。〔09 p9〕
- 解决：**重写（override）`Object` 类的 `toString()`**，必须命名为 `toString()` 且返回 `String`。〔09 p10〕

```java
public String toString() {
    return "Account number: " + accNo + "\n"
         + "Account name: "   + accName + "\n"
         + "Balance: "        + balance;
}
```

### 1.4 方法重载 Method Overloading（高频考点）〔09 p14〕

- **定义**：同名方法、但**参数集合不同**（类型 / 个数 / 顺序不同）。
- 编译器靠**方法签名（signature = 方法名 + 参数类型与顺序）**来区分。
- **⚠️ 易错点**：**返回类型不参与区分**！不能仅靠返回类型不同来重载两个同签名方法。
- 例：两个 `BankAccount` 构造器 `(int, String)` 与 `(String, int)` 是不同的构造器（参数顺序不同）→ 这就是重载。〔09 p6〕

### 1.5 重写 vs 重载（必考辨析）

| | 重载 Overloading | 重写 Overriding |
|---|---|---|
| 关系 | 同一个类内（或继承中）同名不同参 | 子类重定义父类**同名同参**方法 |
| 区分依据 | 参数列表不同 | 签名完全相同 |
| 返回类型 | 不参与区分 | 必须兼容 |
| 典型 | 多个构造器 | 子类 `treatPatient()` 覆盖父类 | 〔09 p14〕〔11 p9〕〔12 p15〕

## 2. 程序设计基础：从需求到代码（Sink a Dot Com）

> 出处：10 课件〔10 p1-18〕。这是一个"自顶向下设计 + 测试驱动"的完整范例。

### 2.1 设计流程（先英文逻辑、后 Java 代码）〔10 p5-6〕

1. 先用**英文**写清程序交互，不写 Java。
2. 画**流程图（flowchart）**：圆=开始/结束，菱形=判断点（decision），矩形=动作点（action）。〔10 p5〕
3. 简化第一版：先做"1 个 Dot Com、一行而非二维网格"的最简版，再迭代改进。〔10 p7〕

### 2.2 Prep code（伪代码）〔10 p10-11〕

prep code 是聚焦逻辑、不纠结语法的伪代码。`checkYourself()` 方法逻辑：转 int → 遍历位置数组 → 命中则 `numberOfHits++`；命中数=3 返回 `"kill"`，否则 `"hit"`，未命中 `"miss"`。〔10 p11〕

### 2.3 测试驱动：为什么先写测试？〔10 p12-13〕

- 写完类**不能直接用，必须先测**。写测试代码能澄清"方法到底要做什么"。
- 测试 `checkYourself()` 步骤：实例化对象 → 设位置 `{2,3,4}` → 造假 guess → 调用 → 打印结果对比预期。〔10 p12-13〕

### 2.4 增强 for 循环 enhanced for loop（本周新语法）〔10 p14〕

```java
for (int i : this.locationCells) {   // 等价写法 ↓
    if (guess == i) { ... }
}
// 等价于：
for (int i = 0; i < locationCells.length; i++) {
    if (guess == locationCells[i]) { ... }
}
```

### 2.5 `SimpleDotCom` 第一版关键代码〔10 p14〕

```java
public String checkYourself(String stringGuess) {
    int guess = Integer.parseInt(stringGuess);   // String 转 int
    String result = "miss";
    for (int i : this.locationCells) {
        if (guess == i) { result = "hit"; this.numberOfHits++; break; }
    }
    if (this.numberOfHits == this.locationCells.length) { result = "kill"; }
    return result;
}
```

### 2.6 main() 与 GameHelper〔10 p15-16〕

- `GameHelper` 是预写好的"ready-baked"类，负责取用户输入 `helper.getUserInput(...)`，先不关心其内部实现。〔10 p16〕
- 随机起点：`int randomNum = (int)(Math.random()*5);` 位置为 `{randomNum, +1, +2}`。〔10 p16〕

### 2.7 ⚠️ 第一版的 Bug〔10 p17〕

## 3. 继承与抽象类 (1)：继承、多态、抽象类

> 出处：11 课件〔11 p1-41〕。本周分量最重的一份。

### 3.1 实例变量决定对象身份〔11 p2〕
实例变量使每个对象**独一无二**；状态相同的两个对象**不是**同一个对象。

### 3.2 聚合 Aggregation (has-a)〔11 p4-5〕
- 无专门关键字，表现为"对象是类的实例变量"。
- 例：`RangeRover` 里 `Tire[] array = new Tire[4]` → Car has-a Tire；一副牌 has-a 多张牌。

### 3.3 继承 Inheritance (is-a)〔11 p6-9〕
- 用 `extends`，又叫 父/子类、超类/子类（superclass/subclass）。
- 子类**继承**父类的属性与操作；子类是父类的**特化（specialisation）**。
- 子类通过**重写（override）**继承来的方法实现特化。例：`Surgeon extends Doctor` 重写 `treatPatient()`。〔11 p9〕

**Doctor 类图记忆点**〔11 p10-13〕：
- `Surgeon` 实例变量个数 = 1（继承 `worksAtHospital`）。
- `FamilyDoctor` 实例变量 = 2（自有 `makesHouseCalls` + 继承 `worksAtHospital`）。
- 方法同样被继承（`treatPatient()`），子类可再覆盖。

### 3.4 访问修饰符与继承（必考）〔11 p15-17〕

| 修饰符 | 是否被子类继承 | 说明 |
|--------|----------------|------|
| `public` | ✅ 继承 | 任何地方可见 |
| `protected` | ✅ 继承 | 子类 + 同包可见 |
| `private` | ❌ 不继承、子类不可见 | 仅本类 |

⚠️ 例题〔11 p17〕：`protected` 成员在"同包的非子类"中可访问；但 `private` 方法在任何情况下都不可被外部访问。

### 3.5 设计原则：is-a / has-a 不要搞反〔11 p20-21〕
- `Refrigerator extends Kitchen` ❌ → 应是 Kitchen **has-a** Refrigerator（聚合）。
- 继承链：B extends A、C extends B ⇒ C is-a A 且 is-a B。is-a **只能向上成立**，反向不成立（Shape 不一定是 Rectangle）。〔11 p21〕
- 继承的好处：**避免代码重复 + 允许特化**。

### 3.6 用继承改进设计：Creature 例子〔11 p22-26〕
- 把 Turtle / Rabbit 的共同部分（name, tailType, color, speed, run, swim）抽到父类 `Creature`，子类只加/改特有部分。
- 子类用 `extends Creature`，对需要特化的方法（如 `run()`）重写；Turtle 没有 `sleep()` 就不能调 `t.sleep()`。〔11 p25-26〕

### 3.7 多态 Polymorphism（核心）〔11 p29-30, p38-40〕

- **定义**：用单一父类定义、配合不同子类型使用。
- 关键写法：
  ```java
  Creature aCreature = new Turtle();   // 把子类当父类型对待
  Creature c = new Rabbit();           // 同样允许
  Creature[] cArray = new Creature[7]; // 数组可同时放 Rabbit 和 Turtle
  ```
- ⚠️ 方向性：Turtle is-a Creature 成立；反向不一定（一个 Creature 不一定是 Turtle）。〔11 p29〕
- 多态实战：`CreatureList` 用 `Creature[]` 可容纳"任何 Creature，甚至还没写的子类"。〔11 p38〕
- 更好用 **ArrayList**：`ArrayList<Creature>` + 增强 for 遍历调用 `c.run(...)`，无需知道具体子类型（因为 `run()` 定义在 Creature）。〔11 p40〕

### 3.8 抽象类 Abstract Class 与抽象方法 Abstract Method（必考）〔11 p31-36〕

- 动机：`new Creature()` 这种"模板对象"不该存在（"有些对象本就不该被实例化"）。〔11 p31〕
- `abstract class`：**编译器不允许实例化**，唯一用途是被继承（extended）。〔11 p32〕
  ```java
  public abstract class Creature { ... }
  Creature c = new Creature();  // ❌ 编译错误
  Creature c = new Rabbit();    // ✅
  ```
- **非抽象类 = 具体类（concrete class）**。〔11 p34〕
- `abstract` 方法：只有声明、无方法体，**子类必须重写**：
  ```java
  public abstract int run(int duration, boolean zigzag);  // 注意以分号结尾，无 { }
  ```
- ⚠️ 规则〔11 p36〕：子类必须实现父类**所有**抽象方法，**否则它自己也必须声明为 abstract**。

## 4. 继承与抽象类 (2)：访问控制、构造器、this、Square

> 出处：12 课件〔12 p1-15〕。以 Rectangle/Square 复习封装与继承细节。

### 4.1 默认访问与改进〔12 p2-3, p8〕
- 不加修饰符的实例变量是**默认访问（default/package access）**，并非真正 public（课件特别强调）。〔12 p3〕
- 改进：把 `width/height` 设 `private`，则 `r1.height = 10;` 在 main 中报错；但同类内的 `area()/draw()` 仍可访问私有成员。〔12 p8-9〕
- 默认原则：**所有实例变量都设 private**。〔12 p9〕

### 4.2 对象变量默认值与初始化〔12 p6-7〕
- 仅声明 `Rectangle r1;` 时未创建对象，对象变量默认值是 **`null`**（"无对象"）。
- `new` 创建对象时调用**默认构造器（default constructor）**，所有实例变量初始化为各自默认值（int → 0）。〔12 p6〕

### 4.3 访问器 / 修改器约定〔12 p10〕
- getter 与变量同名约定：`getWidth()`。
- setter 可加**校验**：
  ```java
  public void setWidth(int i) {
      if (i >= 0) { this.width = i; }
      else { System.out.println("bad width"); }
  }
  ```

### 4.4 自定义构造器简化创建〔12 p12〕
```java
public Rectangle(int w, int h) { setWidth(w); setHeight(h); }
// 于是：Rectangle r1 = new Rectangle(10, 20);  替代三行 set
```

### 4.5 关键字 `this`〔12 p13〕
对象引用自身。例：`isSquare()` 中 `if (this.width == this.height)`。

### 4.6 子类 Square 继承 Rectangle〔12 p14-15〕
```java
class Square extends Rectangle {
    public Square(int w, int h) {
        if (w != h) { System.out.println("bad square!"); }
        else { setWidth(w); setHeight(w); }
    }
    public Square(int w) { setWidth(w); setHeight(w); }   // 构造器重载
}
```
- Square 继承 Rectangle 全部实例变量与方法（如 `area()`）。
- 子类提供**同名同参**的方法/构造器时，会**覆盖（override）**父类对应版本。〔12 p15〕

## 5. 接口 Interface 与多重继承

> 出处：13 课件〔13 p1-26〕。

### 5.1 为什么需要接口：从抽象类的局限说起〔13 p2-6〕
- 若把 `fly()` 放进 `Creature`，则 Rabbit/Turtle 也"被迫会飞"；设为抽象方法又强制所有子类实现。〔13 p2〕
- 多抽象父类（Bird）能让鸟飞，但 Penguin（不飞的鸟）、Flying Squirrel（会飞但不是鸟）无法优雅表达 → 需要**第二个父类 Flyable**。〔13 p4-6〕

### 5.2 致命菱形问题 Deadly Diamond Problem（必考）〔13 p7〕
- 若 C 同时继承 A、B，而 A、B 都覆盖了 `play()` 且都继承自同一祖先的变量 `i` → 不知道继承哪个版本、`i` 取什么值。
- **结论：Java 不允许类的多重继承（multiple inheritance）**；多重继承只在**接口层面**实现。

### 5.3 接口的本质〔13 p8-9, p13〕
- 接口 ≈ **100% 抽象类**：（SE8 前）没有任何已实现方法，所以不存在"继承到半成品方法"的冲突 → 多重继承不再是问题。〔13 p8〕
- 接口里方法即使不写 `public abstract` 也**默认就是 public abstract**。〔13 p9〕
- 接口像"证书"：声明"我提供这些服务"，调用方把实现当黑盒。〔13 p13〕
- **不能实例化接口**：`Flyable f = new Flyable();` ❌。〔13 p13〕

```java
public interface Flyable {
    void fly();   // 默认 public abstract
}
public class FlyingSquirrel extends Creature implements Flyable {
    public void fly() { ... }   // 必须实现 Flyable
    public void run(int duration) { ... }  // 必须实现 Creature 的抽象方法
}
```

### 5.4 extends vs implements（必考）〔13 p12〕
- 一个类**只能 `extends` 一个父类**（单继承）。
- 一个类**可以 `implements` 任意多个接口**。
- 接口可跨越不同继承树使用（Creature 树与 Alien 树都能实现同一接口）。〔13 p10-11〕

### 5.5 抽象类 vs 接口 对比小结〔13 p15〕
- 两者都**不能被实例化**。
- **若完全不提供方法实现 → 用接口**而非抽象类。
- 类可实现多个接口，但只能继承一个超类。
- 接口是 Java 提供（一种）多重继承的方式。
- **只要类中有一个 abstract 方法，整个类必须声明为 abstract**。
- 抽象类和接口都可含**常量（constants）**，被继承/实现的类继承。

### 5.6 接口里的常量与方法（易错例题）〔13 p16-17, p26〕
```java
public interface Countable {
    int x = 20;  int y = 30;   // 接口字段默认 public static final（常量）
    void counting();
}
```
- ⚠️ 接口字段隐式为 **`public static final`**，引用时用 `Countable.y`。〔13 p16, p19〕
- 若类只实现接口的部分方法 → 该类变为**抽象类**，不能实例化。〔13 p17, p19〕
- Practice Ex3〔13 p26〕：接口里 `int total = total + r + s;`（用未初始化自身）、`public static MAIN = 15;`（缺类型）、`protected int CODE`（接口成员不能 protected）都非法；常量表达式如 `final double circumference = 2*Math.PI*r;` 合法。

### 5.7 正确的接口写法（Practice Ex1）〔13 p14〕
- 接口里方法**不能有方法体**（SE8 前）：`void print() { }` ❌。
- 正确：`interface D { void print(); }` ✅。

### 5.8 接口继承与名称冲突〔13 p20-21〕
- 接口也能 `extends`，且可继承多个：`interface Child extends Father, Mother`。Child 拥有两者全部成员。〔13 p20〕
- 名称冲突规则〔13 p21〕：
  - 同名方法**参数不同** → 都保留（相当于重载）。
  - 同名方法**仅返回类型不同** → 报错。
  - 完全相同 → 只保留一个。
  - 同名常量 → **都保留**，用父接口名作前缀引用：`Father.age` / `Mother.age`。

### 5.9 Java SE8：default 与 static 方法（重点新特性）〔13 p22-24〕
- **default 方法**：让接口新增功能而不破坏已实现该接口的旧类（向后兼容）；**可被实现类覆盖**。
- **static 方法**：接口内的工具方法；**不能被实现类覆盖**，用 `接口名.方法()` 调用。
```java
public interface Interviewer {
    void conductInterview(String name);          // 抽象方法
    default void submitInterviewStatus() { System.out.println("Accept"); }
    static void bookIntRoom(String day, int duration) { ... }
}
// 调用：Interviewer.bookIntRoom("Monday", 1);  mgr.submitInterviewStatus();
```
- ⚠️ 多接口含**相同签名的 default 方法** → 实现类必须覆盖，并用 `接口名.super.方法()` 指定调用哪个：〔13 p24〕
```java
public void show() {
    TestInterface1.super.show();
    TestInterface2.super.show();
}
```

## 6. Object 类与对象比较

> 出处：14 课件〔14 p1-11〕。

### 6.1 "超级类" java.lang.Object〔14 p2〕
- `Object` 是 Java 中**所有类的最终父类**，被每个类隐式继承。
- 常见方法：`boolean equals()`、`Class getClass()`、`int hashCode()`、`String toString()`。
- 为什么不把所有东西都当 Object（如 `Object[]`）？会**丢失能力**：当成 Object 数组就不能再当 Creature 遍历、不能调 `run()/sleep()`。〔14 p2〕

### 6.2 Object 的几个方法〔14 p3-4〕
- `equals()`：判断两个对象是否相等。
- `toString()`：使对象可打印；**不重写就只得到地址**（如 `Turtle@7r234f`）。
- `hashCode()`：每个对象的唯一 ID，通常基于内存地址。
- `getClass()`：返回对象的类（如 `class Rabbit`）。

### 6.3 `==` vs `equals()`（高频必考）〔14 p5-7〕
- 对对象而言，`==` 比较的是**身份/标识（identity，即内存地址）**。两个状态相同但 `new` 出来的对象 `r1 == r2` 为 `false`。〔14 p5〕
- 要按"内容相等"判断需**自己重写 `equals(Object o)`**：
```java
public boolean equals(Object o) {
    Rabbit r = (Rabbit) o;   // 向下转型
    if (r.getName().equals(this.getName()) && ... ) return true;
    else return false;
}
```
- 重写后 `r1.equals(r2)` 可得 `yes`。**两个对象何时算相等取决于你的应用**。〔14 p7〕
- 记忆：**基本类型用 `==` 比值；对象用 `equals()` 比内容、`==` 比地址**。

### 6.4 超类引用与向下转型 downcasting〔14 p8〕
- 子类对象可当超类对待（反之不行）。
- 可建超类引用数组、统一处理。
- **显式强制转换（explicit cast）**：把超类引用转回子类引用（**向下转型 downcasting**）；**仅当该超类引用实际指向子类对象时**才可行。

### 6.5 重写方法与 super〔14 p9-10〕
- 子类可重定义超类方法；子类提到该方法时用子类版本。
- 用 **`super.methodName()`** 访问被覆盖的原超类方法。
- 用 **`super()`** 显式调用超类构造器（默认会隐式调用）；**若显式调用，必须是构造器中的第一条语句**。
```java
public class Subclass extends Superclass {
    public void printMethod() {
        super.printMethod();                       // 调父类版本
        System.out.println("Printed in Subclass");
    }
}
```

## 7. 程序设计基础（再述）：ArrayList 与 Java API

> 出处：TB2-B1〔TB2_B1 p1-26〕。用 ArrayList 修复第 2.7 节的 bug。

### 7.1 数组的问题〔TB2_B1 p2〕
- **固定大小（fixed size）**：不能增长/缩小。
- 增删元素困难、交换需临时变量，且常要改代码。

### 7.2 常用 ArrayList 方法（必背）〔TB2_B1 p3-5〕

| 方法 | 作用 |
|------|------|
| `new ArrayList<Flower>()` | 创建空列表 |
| `add(f)` | 添加元素 |
| `size()` | 元素个数 |
| `contains(f)` | 是否包含（返回 boolean） |
| `indexOf(f)` | 元素位置（**0-based**） |
| `isEmpty()` | 是否为空 |
| `remove(f)` / `remove(index)` | 删除元素 |
| `get(index)` | 取指定位置元素 |

### 7.3 数组 array vs ArrayList（高频对比）〔TB2_B1 p6-7〕

| | 数组 array | ArrayList |
|---|---|---|
| 大小 | 创建时必须定大小 `new String[6]` | 无需 `new ArrayList<E>()`，自动增长 |
| 赋值 | 按索引 `myList[4] = b;` | `add(b)` |
| 取值 | `[ ]` 语法 `myList[4]` | 点记法 `get(4)` |
| 类型 | 直接元素类型 | **参数化（parameterised）** `ArrayList<String>`（Java 5.0 引入） |

⚠️ `<String>` 限定只能放 String；`ArrayList<Rabbit>` 只能放 Rabbit。〔TB2_B1 p7〕

### 7.4 用 ArrayList 修复 Dot Com bug〔TB2_B1 p9-18〕
- 旧 bug：同格多次命中也累加 `numberOfHits`。〔TB2_B1 p9-12〕
- 三种思路：①另建 boolean `hitsArray`（太繁琐）；②命中后改值为 -1（仍繁琐）；③命中即删格并缩小数组（但标准数组不能缩小）→ 引出 ArrayList。〔TB2_B1 p13-15〕
- 改进版 `checkYourself()`：用 `indexOf` + `remove`，列表空即 `kill`，无需 `numberOfHits`：
```java
public String checkYourself(String stringGuess) {
    String result = "miss";
    int index = this.locationCells.indexOf(stringGuess);
    if (index >= 0) {
        this.locationCells.remove(stringGuess);
        if (locationCells.isEmpty()) result = "kill";
        else result = "hit";
    }
    return result;
}
```
- ⚠️ main 中拼接陷阱〔TB2_B1 p18〕：`""+randomNum + 1` 会变成字符串拼接 → `[3,31,32]`；必须 `""+(randomNum+1)` 才得 `[3,4,5]`。

### 7.5 Java 库 / API 与包 package〔TB2_B1 p24-26〕
- 用 API 类需知其**所在包**，如 `ArrayList` 在 `java.util`。
- 两种使用方式：① **import**（常用）`import java.util.ArrayList;`；② 全名 type：`java.util.ArrayList<Rabbit> list = ...`。〔TB2_B1 p25〕
- **`java.lang` 自动导入**（含 `Math.random()`、`System.out.println()`）。〔TB2_B1 p24〕
- 主要包〔TB2_B1 p26〕：`java.lang`（语言基础）、`java.io`（输入输出/序列化/文件）、`java.awt`（GUI 与图形）。

## 8. 改进版完整游戏（综合范例）

> 出处：TB2-B2〔TB2_B2 p1-14〕，自学拓展材料，整合本周所有概念。

### 8.1 需要改什么〔TB2_B2 p3〕
- `DotCom` 类：加 `name` 变量（被击沉时打印名字）。
- `DotComBust` 类（游戏）：要 3 个 DotCom；用 setter 给名字；放到网格（交给 `GameHelper`）；对 3 个都检查；全部击沉才结束；逻辑移出 `main()`。

### 8.2 三个类的职责〔TB2_B2 p4〕
| 类 | 职责 |
|----|------|
| `DotCom` | 知道自己的 name、location，检查猜测 |
| `DotComBust` | 游戏类：造 DotCom、取输入、玩到全死 |
| `GameHelper` | ready-baked 助手：接收命令行输入、生成位置 |

### 8.3 对象协作流程〔TB2_B2 p6-11〕
`main()` 在 DotComBust 类中创建 DotComBust 对象 → 它实例化 GameHelper、实例化装 3 个 DotCom 的 ArrayList → 创建 3 个 DotCom 并经 helper 给位置 → 取用户猜测、让每个 DotCom 自检。

### 8.4 核心代码〔TB2_B2 p12-14〕
```java
// setUpGame(): 造 3 个 DotCom、命名、加入列表、用 helper 给位置
for (DotCom dc : dotComList) {
    ArrayList<String> newLocation = helper.placeDotCom(3);
    dc.setLocationCells(newLocation);
}

// startPlaying(): 列表非空就循环
while (!dotComList.isEmpty()) {
    String userGuess = helper.getUserInput("Enter a guess");
    checkUserGuess(userGuess);
}

// checkUserGuess(): 遍历所有 DotCom，kill 时从列表移除
for (DotCom dc : dotComList) {
    result = dc.checkYourself(userGuess);
    if (result.equals("hit")) break;
    if (result.equals("kill")) { dotComList.remove(dc); break; }
}

// finishGame(): 按 numOfGuesses 是否 <= 18 给不同评级
```

## 9. 高频考点 & 易错点速查

1. **重载看参数、不看返回类型**；重写是同名同参。〔09 p14〕〔12 p15〕
2. **对象比较：`==` 比地址（identity）、`equals()` 比内容**；需自己重写 equals。〔14 p5-7〕
3. **`toString()` 不重写就打印 `类名@hashcode`**。〔09 p9〕〔14 p3〕
4. **抽象类不能实例化**；含 1 个抽象方法则整类必须 abstract；子类必须实现全部抽象方法否则自身 abstract。〔11 p32-36〕〔13 p15〕
5. **接口字段隐式 `public static final`**；接口方法隐式 `public abstract`（SE8 前无方法体）。〔13 p9, p16〕
6. **`extends` 单继承，`implements` 可多接口**；Java 类无多重继承（菱形问题）。〔13 p7, p12〕
7. **SE8 接口可有 default（可覆盖）与 static（不可覆盖）方法**；多 default 冲突用 `接口名.super.方法()`。〔13 p22-24〕
8. **访问修饰符**：private 不被继承；protected 同包+子类；public 全可见。〔11 p15-17〕
9. **`super()` 调父构造器须放第一行**；`super.method()` 调父类被覆盖方法。〔14 p9-10〕
10. **array vs ArrayList**：数组定长、`[ ]`、元素类型；ArrayList 变长、点记法、参数化 `<E>`。〔TB2_B1 p6-7〕
11. **字符串拼接陷阱**：`""+a+1` 是拼接非加法。〔TB2_B1 p18〕
12. **对象变量默认值 `null`**；int 等基本类型字段默认 0。〔12 p6〕
13. **is-a 单向**（子→父成立，父→子不一定）；区分 is-a（继承）与 has-a（聚合）。〔11 p20-21, p29〕
14. **向下转型 downcasting** 仅当超类引用实际指向该子类对象时安全。〔14 p8〕
