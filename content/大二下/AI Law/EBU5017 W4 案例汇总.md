## 案例 1：Netflix Prize 再识别案（Netflix Prize Re-identification）

### ① 案例内容
- 2006 年 Netflix 发起"Netflix Prize"竞赛以改进电影推荐算法，公开了约 **48 万用户**的评分数据集。`[框架 27]`
- 数据集含：随机用户 ID（无姓名）、影片名、星级评分、评分日期。Netflix 宣称数据**已匿名化**，可安全公开。
- 2007 年研究者 **Narayanan 与 Shmatikov** 将数据与 **IMDb 公开评分**（含用户评论与时间戳）比对，成功**重新识别**了数据集中的用户——**少量评分 + 日期即足以唯一定位个人**。`[框架 28]`

### ② 课件中的分析
- 个人数据的定义**不止于显性标识符**：除姓名/住址外，IP、在线标识符、甚至行为模式，依语境都可能是个人数据。`[框架 29]`
- 关注点应放在**潜在可识别性（identifiability）**：即便数据看似匿名，只要能结合其他信息识别个人，即仍属个人数据。
- 由此引出**匿名化 vs 假名化**：真匿名要求"再识别在合理手段下不可能"；本案恰证明所谓"匿名"$\neq$ 真匿名。`[框架 25-26]`

### ③ 这类案例应从什么角度分析
1. **数据是否真正脱离"个人数据"范畴**：用 GDPR Recital 26 / PIPL A.73(IV) 的"合理识别手段"判据（可用技术、时间成本、技术可行性）。`[框架 30]`
2. **链接攻击（linkage attack）风险**：是否存在可与之比对的外部公开数据集。
3. **责任归属**：发布方是否尽到匿名化义务；"自以为匿名"不构成免责。
4. **对 AI 的延伸**：训练数据集若假名化不足，模型可能"记忆"并泄露个人——连接到 **再识别风险（re-identification risk）**。`[隐私 43]`

## 案例 2：数据分类速练 —— 刘一阳哮喘情景（Data Classification Exercise）

### ① 案例内容
课件给出三条对同一医疗事实的不同表述，要求判断各属何种数据、是否受数据保护法约束：`[框架 33]`
- **A**：「Yiyang LIU，2004-03-14 生，住北京朝阳区惠新西街 3 号楼 402，2025-10-10 确诊哮喘」
- **B**：「一名 25–30 岁北京患者，2025 年 10 月确诊哮喘」
- **C**：「患者 ID 58472，生于 14-03-2004，邮编区 100020，2025-10-10 确诊哮喘」

### ② 课件中的分析（参考答案思路）
- **A = 可直接识别的敏感个人数据**：含姓名、精确住址、出生日期 + **健康信息**（GDPR 特殊类别 / PIPL 敏感个人信息），**完全适用**数据保护法。
- **B = 趋向匿名化**：仅年龄段 + 城市 + 月份，单独看难以识别特定个人（但需评估结合其他数据的可能）。
- **C = 假名化数据**：用 ID 替换姓名，但保留出生日期 + 邮编区，**可结合再识别**，组织若持有 ID 对照表则**仍属个人数据**。

### ③ 这类案例应从什么角度分析
1. **逐字段拆解**：哪些是直接标识符、哪些是准标识符（quasi-identifier，如出生日期+邮编）、哪些是敏感属性（健康）。
2. **匿名 / 假名 / 可识别 三分法**：核心看"是否还能再识别"与"密钥是否被分开保存"。`[框架 30-32]`
3. **敏感数据加重义务**：健康数据触发 GDPR 明确法律基础 / PIPL 单独同意 + 必要性证明。`[隐私 44]`
4. **答题技巧**：先识别数据类型 → 再判断适用法律 → 最后说明所需的合规动作（IRAC 思路）。

## 案例 3：OpenAI / ChatGPT（意大利等 DPA 执法）

### ① 案例内容
- 发生**数据泄露**：用户对话内容与**支付信息**被暴露给其他用户。`[隐私 11]`
- 监管认定：为"训练平台底层算法"而**大规模收集并存储个人数据**，**缺乏合法基础**（no legal basis）。

### ② 课件中的分析
- 归入 **GDPR 在 EU 对 AI 模型提供方的执法行动**示例。`[隐私 10]`
- 两条问题线：**安全失效**（违反第 32 条安全义务，导致泄露）+ **合法性缺失**（违反第 6 条，训练抓取无合法基础）。

### ③ 这类案例应从什么角度分析
1. **合法性基础（Article 6）**：训练用大规模数据，是同意还是正当利益？两者对 mass scraping 都极难成立。`[隐私 8]`
2. **安全义务（Article 32）**：是否实施了与风险相称的技术 + 组织措施；泄露是否触发 72 小时通报。`[框架 59]`
3. **目的限制与透明**：用户是否被告知数据将用于训练。
4. **双重违法叠加**：注意区分"收集环节违法"与"运营环节安全失效"两个独立问题。

## 案例 4：DeepSeek 跨境数据传输

### ① 案例内容
- DeepSeek 的**跨境数据传输实践不符合 GDPR**。`[隐私 14-15]`

### ② 课件中的分析
- 作为 **GDPR 跨境传输难点**的现实例证：使用全球云平台、数据流向他国，使合规变得"法律上复杂"。`[隐私 9]`
- 与 **PIPL 数据本地化**形成呼应：中国侧强调本地化 / "区域内训练"，欧盟侧要求接收国有同等保护。

### ③ 这类案例应从什么角度分析
1. **跨境合法机制**：是否具备充分性决定 / SCCs / BCRs + 传输影响评估（TIA）。`[框架 62]`
2. **目的地政府访问法**：接收国法律是否允许政府访问数据（TIA 核心）。`[隐私 37]`
3. **双向合规冲突**：同一公司可能同时面对 EU 出境限制与中国 PIPL 本地化/出境安全评估。`[隐私 36, 40]`
4. **AI 分层视角**：训练管道（最高风险）、模型权重导出（隐性传输）、推理层（数据驻留）各有不同控制要求。`[隐私 37-39]`

## 案例 5：Clearview AI（人脸识别抓取）

### ① 案例内容
- 美国公司从社交媒体（Facebook、Instagram 等）抓取约 **300 亿张**公开照片及元数据（仅公开页面，不含私密账户），含英国与欧盟成员国境内人员。`[隐私 16]`
- 建立**人脸识别数据库**，出售给**美国执法部门**用于人像比对匹配。
- 被欧盟 DPA 处罚 → 争议：为何美国公司因 EU 法律 GDPR 被诉？`[隐私 17]`

### ② 课件中的分析
- **域外效力关键**：GDPR 适用于**非欧盟**公司，只要其活动涉及"**监控欧盟境内个人行为**"（monitoring of behaviour）。`[隐私 17]`
- Clearview 抗辩：仅抓取公开图片、并非"监控行为"；**DPA 不予认同**。
- **三个讨论题（高频考点）**：`[隐私 19]`
  - 公开发布的照片是否构成"个人数据"？
  - 公开发布是否等于同意被抓取？
  - 人脸识别**嵌入向量（embeddings）**是否属于"个人数据"？

### ③ 这类案例应从什么角度分析
1. **管辖权 / 域外适用**：先判断 GDPR 是否适用——看是否"监控行为"或"向 EU 提供商品服务"。
2. **"公开 ≠ 同意"原则**：数据可公开获取，不代表有合法基础再利用；公开不消灭数据保护权。
3. **生物特征数据**：人脸属 GDPR 特殊类别 / PIPL 敏感信息，处理需更高门槛；embeddings 若可识别个人亦属个人数据。
4. **比例与必要性**：执法用途能否正当化大规模、无差别抓取（往往不能）。

## 案例 6：X（Twitter）训练 Grok（2024）

### ① 案例内容
- X 用欧盟用户在平台上的**公开帖子**训练 LLM（Grok），数据含帖文、姓名、观点、信仰、位置等**敏感数据**。`[隐私 21]`
- 用户**未被清楚告知**其帖子会用于训练 LLM。
- X 采用**"默认开启"的同意设置**（default on，用户可 opt-out）；隐私声明称信息"可能"用于训练。`[隐私 22-24]`
- 法律基础主张：**正当利益（Article 6(1)(f)）**。

### ② 课件中的分析
- **noyb 投诉**：未取得训练所需同意；主张 X **缺乏**正当利益。`[隐私 26, 30]`
- "简单解法"论点：GDPR 本可让用户**主动"捐赠"数据**——只要直接征求明确同意，少量用户同意即足够训练；但 X 选择**不告知、不征求许可**直接取用。`[隐私 26]`
- **监管结果**：爱尔兰数据保护委员会（DPC）向高院申请**中止处理**（2024-08-08 听审）；X **同意暂停**处理欧盟/EEA 用户公开帖，未经法院命令即达成。`[隐私 27]`
- **DPA 意见分歧 → 法律不确定性**：ICO / CNIL / EDPB 支持可依赖正当利益；荷兰反对。`[隐私 31]`
- **行业影响论点（X 主张）**：EU 限制可能削弱模型服务欧洲用户的能力、影响内容审核/安全功能、造成竞争劣势。`[隐私 29]`

### ③ 这类案例应从什么角度分析
1. **正当利益三步测试**：目的 → 必要性 → 平衡；抓取常不可见、高风险，用户权利易压倒公司利益。`[框架 54]`
2. **同意的有效性**：GDPR 要求"自由、具体、知情、明确"；**默认开启 / opt-out 一般不构成有效同意**。`[框架 52]`
3. **敏感数据 + 正当利益不兼容**：正当利益**不适用于敏感数据**，而帖文含信仰/政治观点等特殊类别。`[框架 54]`
4. **透明义务**：用户是否被明确告知用途。
5. **监管协作与不确定性**：注意"DPA 间意见不一致"本身就是答题可展开的论点（承认对立观点）。

## 案例 7：CT-GAN —— 恶意篡改 3D 医学影像（Malicious Tampering of 3D Medical Imagery）

### ① 案例内容
- 论文 *CT-GAN: Malicious Tampering of 3D Medical Imagery using Deep Learning*（arXiv:1901.03597）。`[安全 11-13]`
- 攻击者用深度学习（GAN）在 **CT 影像**中**注入或移除病灶**（如肿瘤），篡改后影像足以**欺骗放射科医生与诊断 AI**。

### ② 课件中的分析
- 作为 **AI 安全风险的真实示例**引入，强调"**控制措施是有的，但必须落实**（controls are available but must be put in place）"。`[安全 12]`
- 体现 AI 系统**多组件、各有风险**：威胁针对训练数据 / 模型 / 输入输出通道的**完整性（Integrity）**。`[安全 14]`
- 关联攻击类型：**数据投毒（Data Poisoning）**、**篡改 / 完整性攻击**。

### ③ 这类案例应从什么角度分析
1. **CIA 三性定位**：本案核心是**完整性（Integrity）**被破坏（数据/输出被篡改），而非机密性。
2. **风险公式**：风险 = 可能性 × 影响；医疗场景**影响极高**（误诊、生命危险）→ 需更强控制。`[安全 9]`
3. **针对哪一层**：训练数据管道？推理输入？据此选控制（数据溯源验证、鲁棒训练、访问控制）。`[安全 缓解]`
4. **五类控制**：识别 → 检测 → 预防 → 响应 → 恢复；以及"安全设计/开发/部署/运维"四阶段（NCSC）。`[安全 13, NCSC]`
5. **责任与法律后果**：安全失效可经专门法或一般原则（如侵权法 tort law）追责。`[安全 小结]`

## 案例 8：AI 心理健康聊天机器人（综合情景案例）

### ① 案例内容
- 青少年使用 AI 心理健康聊天机器人，对话含姓名/年龄/学校、心理状况、家庭情况、**自残意念**等极敏感内容。`[聊 15]`
- 训练分三层：基础模型预训练（公共文本，离线历史性）→ 心理健康微调（专业/合成对话 + RLHF，**主动避免真实病患数据**）→ 部署期系统提示 + 安全分类器 + 升级逻辑。`[聊 9-13]`

### ② 课件中的分析
- **核心论点**：最大风险**不在训练，而在部署**——在情感信任、半匿名、安全治理不完善下处理极敏感数据。`[聊 14, 26]`
- **隐私风险**：(1) 处理特殊类别 / 敏感 / **儿童数据**（"模型不记得，但系统记得"）；(2) 留存与二次使用 = 新处理，需父母同意；(3) 虚假匿名感（期望落差即风险）。`[聊 15-18]`
- **安全风险（CIA）**：机密性（日志泄露）、完整性（提示注入削弱护栏）、可用性（断服致痛苦、过度依赖）。`[聊 19-21]`
- **模型安全特有关切**：记忆风险（复述旧对话）、对齐衰减、模型不透明。`[聊 22-25]`

### ③ 这类案例应从什么角度分析
1. **数据敏感性叠加**：特殊类别 + 儿童数据 → **双重加重保护**，需明确法律基础/单独同意 + 父母同意。
2. **生命周期 + 分层视角**：区分训练期 vs 部署期风险，落到七层组件定位问题。
3. **CIA + 模型安全双轨**：既看传统机密/完整/可用，又看 AI 特有的记忆/对齐/不透明。
4. **二次使用判定**：对话被复用于训练/分析 = 新处理，触发新的合法基础与告知义务。`[聊 17]`
5. **脆弱群体与衡平**：青少年的合理期望、心理伤害的特殊性，影响"影响（Impact）"评估。

## 通用方法论：分析这类 AI 法律案例的统一框架

> 课件反复强调：**不要只罗列规则，要把法律适用到事实**。建议用以下顺序展开（即 IRAC）。`[聊 6]`

### 第一步：定位（在哪一层、哪个生命周期）
- 用 **AI 七层模型**（模型 / 训练数据 / 推理 / 应用 / API / 基础设施 / 人为治理）定位风险发生处。`[框架 6]`
- 区分**训练期 vs 部署期**——隐私案例多数真正风险在部署。`[聊 14]`

### 第二步：定性数据（决定义务强度）
- 个人数据？敏感 / 特殊类别？儿童数据？匿名 / 假名 / 可识别？`[框架 24-32]`
- 敏感数据 → GDPR 明确法律基础 / PIPL 单独同意 + 必要性。

### 第三步：选定法律 + 合法性基础
- 哪个法域？GDPR / PIPL / CCPA？是否有**域外效力**（监控行为 / 提供服务）？`[隐私 17]`
- 合法基础：同意（有效性？默认开启无效）vs 正当利益（三步测试，不适用敏感数据）。`[框架 52-54]`

### 第四步：套用具体义务与原则
- **七大原则**：合法公平透明、目的限制、最小化、准确、存储限制、完整保密、问责。`[框架 44]`
- **安全**：GDPR 第 32 条 / PIPL 第 9 条；技术 + 组织措施；72 小时通报。`[安全 18]`
- **跨境**：充分性 / SCCs / BCRs / TIA；中国安全评估 + 本地化 + 单独同意。`[框架 62-64]`
- **自动化决策**：GDPR 第 22 条 / PIPL 透明 + 拒绝权。`[隐私 48]`

### 第五步：安全案例叠加 CIA + 风险管理
- 定位 **CIA**（机密 / 完整 / 可用）哪一性受损。`[安全 18]`
- **风险 = 可能性 × 影响**；高影响场景需更强控制；五类控制（识别/检测/预防/响应/恢复）。`[安全 9-13]`

### 第六步：结论与衡平
- **承认对立论点**并论证立场（如正当利益的 DPA 分歧）。`[聊 6, 隐私 31]`
- 权利非绝对：安全 / 司法 / 公共健康可限制，但须**合法、必要、相称**。`[框架 65]`
